### 1. Два модуля пути обучения с одинаковым id `frontend` (высокий) — ИСПРАВЛЕНО

**Исправление:** старый модуль удалён из `curriculum.ts`. Его 8 уникальных дуэлей перенесены в `module-frontend.ts`; карточка `cdn` уже есть в `web-basics`, `websocket-gateway` в новом модуле, задача `ds-notification-service` в `platform`. Прогресс игроков хранится по id шагов, поэтому миграция не нужна. Добавлен `src/learn/curriculum.test.ts`: уникальность id модулей и существование всех `requires`. Ниже описание исходной проблемы.

`src/learn/curriculum.ts:205` объявлял модуль `frontend` («Фронтенд-архитектура», 10 шагов, босс `ds-notification-service`), а в конце массива добавляется `frontendModule` из `module-frontend.ts` с тем же `id: 'frontend'` (28 шагов, босс `fe-ssr-meltdown`).

Последствия:

- `getModule('frontend')` всегда возвращает **первый** модуль: страница `/path/frontend` для второго модуля недостижима, клик по нему на карте откроет старый;
- на карте пути (`pages/Path.tsx`) у React Flow два узла с одинаковым id: узлы и рёбра накладываются, React предупреждает о дублирующихся ключах;
- достижения «Первый модуль» и «Полпути» и `nextStep()` считают оба модуля отдельно.

Новый модуль, судя по коммиту `6469e3a`, должен был заменить старый, но старый забыли удалить.

### 2. Утверждение «каждый сценарий проверен ботом» не подкреплено тестами (средний)

README трижды пишет, что обычные, «Наследство» и хардкор-сценарии проверены ботом (без действий проигрыш, с правильной стратегией победа). В `src/sim/engine.test.ts` нет ни одного импорта файлов сценариев; тесты проверяют только механику на синтетических графах. Любая правка цифр движка может незаметно сделать сценарий непроходимым или тривиальным.

Рекомендация: добавить `scenarios.test.ts`, который для каждого сценария (а) прогоняет его без действий через логику `checkScenario` из `server/scenario.ts` и (б) применяет эталонную стратегию из `debrief` как список изменений графа по минутам.

### 3. oxlint падает на `useItem` (низкий, ложное срабатывание)

`src/sim/SimGame.tsx:76, 96, 108, 113`: правило `rules-of-hooks` принимает метод стора `useItem` (потратить перк) за React-хук. `pnpm lint` возвращает ненулевой код. Исправление: переименовать действие в `consumeItem` (в `store.ts`, `watcher.ts` и местах вызова).

### 4. Бэкап текущего дня перезаписывается при каждом сохранении (низкий)

`server/progress.ts` пишет `backups/<name>-<день>.json` при каждом PUT. Если в течение дня прогресс испортится (например, `reset()`), бэкап этого дня тоже испортится; спасут только предыдущие дни. Можно писать бэкап только если файла за сегодня ещё нет.

## Риски и ограничения

- **ИИ-генератор сценариев отстаёт от движка.** `scenarioSchema` разрешает только 6 старых событий и не знает про `zoneDown`, `stall`, `loop`, `enqueue`, `degrade`, `restartLoop`, knobs, зоны и асинхронные SLO. Если ни одна из 3 попыток не прошла плейтест, сервер всё равно возвращает последнюю (непроверенную) версию без пометки.
- **ИИ-сценарии не дают XP**, хотя сохраняются в прогресс (`totalXp` перебирает только встроенные массивы).
- **API без аутентификации.** Рассчитан на localhost. Если открыть порт 5801 наружу, любой сможет расходовать лимиты Claude и перезаписать прогресс.
- **Приватный пакет компании попадает в бандл** при локальной сборке (`import.meta.glob(..., { eager: true })`). CI-сборка безопасна (папки нет в git), ручной деплой локального `dist` нет.
- **GitHub Pages без ИИ.** Опубликованная версия показывает кнопки ИИ-функций, которые падают с ошибкой «AI-сервер не отвечает». Стоит скрывать их по флагу сборки или показывать пояснение.
- **Один бандл 3.9 МБ.** Весь контент (уроки, справочник, сценарии) грузится сразу. Ленивые маршруты (`React.lazy` для страниц) заметно ускорят первую загрузку, особенно на Pages.
- **Каждый ИИ-вызов это новый процесс CLI.** Холодный старт несколько секунд; параллельные запросы плодят процессы без ограничения.
- **Нет ограничений на размер ввода** в промптах (история интервью, ответы). Длинная сессия интервью растёт линейно и замедляет каждую реплику.

- Детерминированный движок с понятной моделью (M/M/1, явные константы с комментариями) и хорошим покрытием механики тестами.
- Генерация ИИ-контента с проверкой результата тем же движком и обратной связью в модель.
- Аккуратное хранение прогресса: атомарная запись, бэкапы, защита от затирания пустым состоянием, `sendBeacon` при закрытии вкладки.

- Пароли CTF живут только на сервере.
- Контент проверяется автоматически на ссылки, стиль и подсказки длиной ответа.
