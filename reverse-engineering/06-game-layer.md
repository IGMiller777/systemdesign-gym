# 06. Игровой слой и прогресс

Логика разнесена так, чтобы не было циклических импортов: состояние и формулы XP в `src/store.ts`, определения (достижения, квесты, магазин) в `src/game/defs.ts`, реакция на изменения в `src/game/watcher.ts`, уведомления в `src/game/Toaster.tsx`.

## Ключи результатов

Всё, что игрок проходит, записывается методом `record(key, score)` в `results[key] = { best, attempts[] }` (best это максимум по попыткам). По префиксу ключа понятно, что это:

| Ключ | Что | Порог «пройдено» |
|---|---|---|
| `<taskId>` (без двоеточия) | Задача | > 0 |
| `concept:<id>` | Урок | ≥ 66 |
| `card:<id>` | Квиз карточки | ≥ 66 |
| `explain:<entryId>:<aspect>` | «Объясни сам» | ≥ 60 |
| `sim:<scenarioId>` | Дежурство | > 0 |
| `daily:<YYYY-MM-DD>` | Тренировка дня | есть запись |
| `def:<levelId>` | Blue Team (звёзды × 33) | > 0 |
| `ctf:<n>` | CTF уровень n | > 0 |
| `interview:<id>` | Mock-интервью | балл |
| `feat:<flawless|penny|no-perks>` | Особые победы в дежурстве | > 0 |
| `duels:streak` | Лучшая серия побед в дуэлях | число |

Отдельно хранится `srs[itemId] = { box, due }` для интервального повторения (дуэли, вопросы квизов, оценки, «объясни сам»).

## XP и звания

`totalXp(results)` пересчитывается целиком из результатов (XP нигде не хранится, поэтому формулы можно менять задним числом):

| Источник | XP |
|---|---|
| Задача | `task.xp × best / 100` |
| Сценарий | `level × 40 × best / 100`; хардкор как уровень +2, «Наследство» как +1 |
| Карточка освоена | 20 |
| Урок пройден | 15 |
| «Объясни сам» ≥ 60 | 10 |
| Тренировка дня | 30 |
| Blue Team | `best × 0.6` (до ~60) |
| CTF уровень | 30 |
| Mock-интервью | `best × 1.5` (до 150) |

ИИ-сценарии в XP не входят: в `totalXp` перечислены только встроенные массивы.

Звания (`src/lib/blocks.ts`): Intern 0, Junior 100, Middle 300, Senior 700, Staff 1300, Principal 2000.

**Серия (streak):** число подряд идущих дней в `days[]`, заканчивая сегодня или вчера. День добавляется при любом `record`.

## Кредиты 🪙

- **1 кредит за каждые 4 XP** (`XP_PER_CREDIT = 4`). README говорит «1 XP = 1 кредит», это устарело: код и миграция v1 пересчитали экономику.
- Награды за квесты (10–20) и сундук за все три квеста дня (`CHEST_REWARD = 30`).
- Награды за достижения (5–165).
- Журнал `ledger`: последние 50 изменений баланса с причиной.

## Watcher

`startGameWatcher()` запускается в `main.tsx` только **после** гидрации стора, иначе загрузка сохранения выглядела бы как огромный прирост XP. При каждом изменении `results`, `srs`, `inventory` или `owned`:

1. для новых попыток определяет тип события квеста по префиксу ключа и увеличивает счётчик дня (`events[day][type]`);
2. считает прирост XP, начисляет кредиты, показывает тост;
3. показывает тост о повышении звания;
4. продвижение дуэли в SRS (`box` вырос) считается событием `duel`;
5. проверяет все достижения и выдаёт новые с наградой.

При старте также применяется **заморозка серии**: если пропущено 1–2 дня и в инвентаре есть `perk-freeze`, пропуски закрываются (только если они соединяют с существующей серией).

## Квесты дня

Пул из 11 квестов (урок, карточка, 3 дуэли, 2 задачи, объяснение, тренировка, дежурство, «Наследство», Blue Team, CTF, интервью). Каждый день детерминированно по дате выбираются 3 (`questsFor(day)`). Выполненный квест забирается вручную (`claimQuest`) в профиле.

## Достижения

32 штуки, 2 секретных («Шопоголик», «Сова» за занятия с 0 до 5 утра). Примеры: «Первая кровь», «Профессор» (все уроки), «Полная колода», серии 3/7/30 дней, «Ветеран» (все 8 базовых дежурств), «Наследник», «Без единой царапины» (дежурство со 100% здоровья), «Red Team» (CTF 6), «Три трека» (интервью по трём трекам на 60+), «Стафф».

## Интервальное повторение

`review(itemId, ok)`: верный ответ переводит в следующий ящик (до 4), ошибка возвращает в ящик 0. Следующее повторение через `[1, 3, 7, 21, 60]` дней в зависимости от ящика.

## Сброс

`reset()` обнуляет весь прогресс, кроме тостов. Файл на диске перезапишется пустым состоянием, и бэкап **сегодняшнего** дня тоже (сервер пишет бэкап при каждом сохранении). Бэкапы прошлых дней в `data/backups/` останутся: восстановить прогресс можно, скопировав нужный файл в `data/sysdesign-gym.json` при остановленном приложении и очистив localStorage.
