# 07. Инструкция: запуск, разработка, деплой

## Требования

| Что | Версия | Зачем |
|---|---|---|
| Node.js | 24 (CI использует 24; проверено на 24.16) | Vite 8, `import.meta.dirname`, `--watch` |
| pnpm | 11 (проверено на 11.7) | Менеджер пакетов, lock-файл `pnpm-lock.yaml` |
| Claude Code CLI | любая актуальная, команда `claude` в `PATH` | Все ИИ-функции |
| Подписка / логин Claude Code | — | CLI должен быть авторизован (`claude` один раз запустить вручную) |

Без Claude CLI приложение запускается и работает, кроме ИИ-функций: проверка дизайна (L4–L6), «объясни сам», наставник, mock-интервью, CTF, постмортем, генерация сценариев.

`pnpm-workspace.yaml` запрещает сборочные скрипты `esbuild` (`allowBuilds: esbuild: false`); Vite 8 работает на rolldown, так что это не мешает.

## Установка

```bash
pnpm install
```

## Запуск

Оба процесса (web + api):

```bash
pnpm dev
```

- Приложение: http://localhost:5800
- API: http://localhost:5801 (напрямую обычно не нужен, Vite проксирует `/api`)

Другая модель для ИИ-проверок (по умолчанию `sonnet`):

```bash
GRADER_MODEL=opus pnpm dev
```

Другие порты (например, если 5800 занят; `strictPort` не даст Vite молча сменить порт):

```bash
WEB_PORT=5802 API_PORT=5803 pnpm dev
```

На macOS можно дважды кликнуть `scripts/dev.command` в Finder: скрипт сам найдёт свободную пару портов в диапазоне 5800–5809, запустит оба процесса и откроет браузер.

По отдельности:

```bash
pnpm dev:web
```

```bash
pnpm dev:api
```

## Проверки качества

Тесты движков симулятора, Blue Team и структуры пути обучения (Vitest, 65 тестов):

```bash
pnpm test
```

Типы:

```bash
./node_modules/.bin/tsc -b
```

Линтер (oxlint; сейчас выдаёт 4 ложных срабатывания, см. [08-findings.md](08-findings.md)):

```bash
pnpm lint
```

Проверка текстов уроков и справочника по стайлгайду:

```bash
./node_modules/.bin/tsx scripts/check-content.ts
```

Порядок уроков по пути обучения (нужен для ссылок «Что дальше»):

```bash
./node_modules/.bin/tsx scripts/check-content.ts --order
```

## Сборка

```bash
pnpm build
```

Результат в `dist/` (один JS-чанк ~3.9 МБ, ~1.1 МБ gzip). Локальный просмотр сборки (без API-прокси, ИИ работать не будет):

```bash
pnpm preview
```

## Деплой на GitHub Pages

Автоматически на push в ветку `main` (`.github/workflows/pages.yml`). Однократная настройка в репозитории GitHub: Settings → Pages → Source: **GitHub Actions**.

Сейчас локальная ветка называется `master`, а workflow слушает `main`. Чтобы деплой сработал, пушьте в `main` (или запустите workflow вручную через `workflow_dispatch`).

На Pages работает только клиентская часть, прогресс хранится в localStorage браузера. ИИ-функции там недоступны.

## Где лежат данные

| Путь | Что | В git |
|---|---|---|
| `data/sysdesign-gym.json` | Прогресс игрока (основная копия) | нет |
| `data/backups/sysdesign-gym-YYYY-MM-DD.json` | Ежедневные бэкапы, последние 14 | нет |
| localStorage `sysdesign-gym` | Зеркало прогресса | — |
| localStorage `interview-session` | Текущая сессия интервью | — |
| `src/company/*.ts`, `docs/bothelp/` | Приватный пакет компании | нет, никогда не коммитить |

### Перенос прогресса на другой компьютер

Скопируйте `data/sysdesign-gym.json` в ту же папку нового клона и запустите `pnpm dev`. При загрузке выбирается копия с большим числом результатов, поэтому пустой localStorage нового браузера файл не затрёт.

### Восстановление из бэкапа

1. Остановите `pnpm dev`.
2. Скопируйте нужный `data/backups/sysdesign-gym-<дата>.json` в `data/sysdesign-gym.json`.
3. В браузере удалите ключ `sysdesign-gym` из localStorage (DevTools → Application → Local Storage), иначе победит копия с большим прогрессом.
4. Запустите `pnpm dev`.

## Подключение своей компании

Создайте `src/company/<имя>.ts` с экспортом `companyPack` типа `CompanyPack` (`src/company.ts`): название, абзац о компании, граф песочницы и список сценариев. Появятся раздел «Моя компания» в дежурствах и маршрут `/sandbox/company`. Папка в `.gitignore`.

Если собираете `dist` локально с этой папкой, пакет попадёт в бандл. Не публикуйте такую сборку.

## Частые проблемы

| Симптом | Причина и решение |
|---|---|
| «AI-сервер не отвечает (HTTP 5xx). Запущен ли pnpm dev:api?» | API не запущен или упал. Смотрите вывод процесса `api` в терминале |
| `claude exited 1: …` | CLI не авторизован или не найден в `PATH`. Запустите `claude` вручную и войдите |
| `cannot parse claude output` | Модель вернула не-JSON для схемы. Повторите запрос; при частых ошибках попробуйте `GRADER_MODEL=opus` |
| Vite: `Port 5800 is in use` | Задайте `WEB_PORT`/`API_PORT` или используйте `scripts/dev.command` |
| Прогресс «пропал» после очистки браузера | Он в `data/sysdesign-gym.json`, если API был запущен. Проверьте файл и бэкапы |
| ИИ-ответы медленные (5–30 с) | Каждый вызов это новый процесс `claude -p`. Наставник стримит ответ, остальные ждут целиком |
| Генерация сценария долгая | До 3 попыток с плейтестом движком; каждая это отдельный вызов модели |
